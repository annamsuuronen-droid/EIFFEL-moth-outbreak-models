## Count, effort and missingness preparation

[Code findings v2](SOURCE_CODE_FINDINGS_v2.csv) provides exact source/line references. Retained primary predictive S1/S2a models **annual integer total_count**, not log1p counts or a seven-day standardized response. It deduplicates consistent sample/species counts across buffers, sums finite-count intervals, requires at least4intervals and28effort days, and constructs `Loff=log(total_effort_days/7)`. Annual-index/log1p columns are derived summaries, not the Poisson response. Missing Y cells receive neutral offset; observed cells require positive effort. Preserve these defenses.

The primary builder distinguishes **absent species rows** (zero-filled under an explicit assumption) from **present rows with missing counts** (not zeroed; excluded from that species' annual count and effort). That distinction may already have been lost upstream: `moth_species_balance_corrected.R` sums counts without `na.rm`, then `replace_na(count,0)` zeroes an NA sum as well as an absent species combination. This is a demonstrated code risk, **not proof that the executed model data contain erroneous zeros**. Determine the active producer and actual missing-source records before changing data.

Other unresolved preparation risks:

- The corrected preparation script clamps nonpositive date differences to1day; the other retained preparation script marks nonpositive durations missing. Their overlapping outputs and the active revision are unproven. A primary positive-effort check cannot detect an earlier clamped error.
- Sampling events are reconstructed from positive species records across the whole source. An event with other species establishes an observed zero for a target only if sampling/reporting protocols support that interpretation. A completely all-zero event absent from the source cannot be distinguished from no sampling without trap-operation records.
- Exact duplicate raw rows are removed in the corrected script; repeated nonidentical count records are summed by sample/species. Duplicate buffers are controlled later, but trap identity, metadata joins, overlapping intervals and original duplicate semantics still need source evidence.
- January–March brumata/fagata observations are assigned a previous `flight_year` in one preparation script; the HMSC builder groups the supplied `year`. The active calendar/flight-year/GIS mapping is unresolved. This affects yearly counts and lag interpretation.
- Prepared GIS/annual/lag2/filled-year producer evidence is absent. The original manifest does not supply an exact allowlisted GIS-ready model CSV for safe extraction. No substitute path/file is invented.
- `extreme_annual_counts_verified=TRUE` is a configuration assertion that bypasses a gate, not the original extreme-verification record.

Retained effort-offset summaries report exp(Loff) minimum4, median9 and maximum25.7143 across species (under the seven-day interpretation:28,63,180days). ## PPC and occurrence reconciliation

Retained C+D source explicitly uses `predict(...,Loff=model$Loff,expected=FALSE)` for realized-count PPCs and calculates presence as `1-mean(realized==0)`. Its expected-count explanatory fit is separate, and final occurrence columns are replaced with realized-occurrence metrics. Thus the fagata zero PPC cannot simply be dismissed as the generic expected-count occurrence bug. Verify the exact saved producer/settings and Y/Loff first; posterior sampling uncertainty, preparation and likelihood inadequacy remain possible explanations.

The three v4 generic occurrence RMSEs **exactly equal sqrt(observed zero fraction)**; each generic AUC is0.5 and Tjur0. Dedicated occurrence exports instead contain nonconstant discrimination. [Reconciliation table](OCCURRENCE_RECONCILIATION.csv) reproduces this identity. Under a positive expected-count representation, testing exact zero yields an always-present probability; the identity explains the recorded pattern. Exact v4 producer is missing, so its implementation is not declared reconstructed.

S5 producer code supplies `expected=TRUE` predictions to `evaluateModelFit` without the dedicated realized-occurrence replacement. Its generic occurrence columns therefore do not measure realized occurrence discrimination. This is a **reporting/estimand problem**, not by itself evidence that the fitted posterior is wrong. Retain all originals, use dedicated realized-occurrence exports with their in-sample scope, and keep expected-count abundance summaries distinct. Recalculating missing realized metrics from an existing posterior may later be useful; this workflow does not generate fresh predictive draws or replace saved outputs.

The offset-corrected autumnata mean/maximum PPC mismatch persists alongside fagata zeros. Earlier PPCs lacking explicit offset handling are historical evidence and must not substitute for the corrected final PPCs. Recovered corrected PPCs already include the extreme; removing/winsorizing it or tuning to held-out loss is not permitted.
